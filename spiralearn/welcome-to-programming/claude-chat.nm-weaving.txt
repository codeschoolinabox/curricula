programming has always been about controling how data is processed, stored and flows through a machine.  conventionally you write text instructions for the machine, this was a compromise between formats that humans can think in and computers can (relatviley) easily store, represent, parse and manipulate.  but these languages are stricter and differenter than human languages because while to us we think of it as _language_, to the computer the language is interpreted as a _data structure_, our syntax and semantics need to be perfect since compilers can't interpret menaing or intention, just the data structures.  But what exactly is this controlling?  Unless you're writing assembly(?), your programming language controls a _virtual machine_ (terminology?).  This is a higher-level imaginary machine / model of computation / memory system / ... which your language directly instructs.  Then these instructions are tranlsated to a lower language to a lower lanaguage to a lower ... until your instructions are finally in a form the hardware understands.  what's great about this is you don't need to understand anything lower than the lanaguages _notional machine_ to be an effective programming in the language!  the language interpreter manages optimizations between this notional level and hardware, it's not something you need to understand at this point.  so where am I going with this?  it's this:  computer programming at this point is about controling a notional computaitonal machine, you wirte specific instructions for how it should carry out your computation.  up to this point in history you had to thoroughly understand this notinoal machine _and_ the language to control it.  now that LLMs exist it's still very helpful to understand how this notional machine works so you can design effective and efficient computational solutions, BUT, now you don't need to master _all_ of the language that controls it!  You need to understand what the notinoal machine affords, what the instructions can and can't make it do, but now you can discuss with an LLM to workshop and clarify your ocmputaitonal intentions for the notional machine you're programming, then delegate most of the specific instruction writing to the LLM once your objective is clearly stated in terms of the notional machine.  then you need to understand the NM and instruction set (code) well enough to help debug and review.
