# StudyLenses — checkpoint

The full instrument, live, with the built-in JEJ level, the injected scaffolding
level, the three ported lenses (parsons and writeme in the Source select;
debug-props is panel-excluded — reachable only as a focus request), and two
page-injected lenses: "notes" (self-recommending) and `spellme`, in the **Tokens
· spelling** station.

`spellme` is injected here **while it is being built**, so its surface is
incomplete on purpose — this page is where its sandbox checkpoints are
exercised. It is deliberately NOT registered in the built-in roster, so no
learner route reaches it; when it is, this injection is removed in the same
commit, because joining a name that is already built in throws.

Both of `spellme`'s attempt thresholds are pinned to **zero** here, and that is
a checkpoint fixture rather than a recommended setting. Its one-more-character
field and its way past are gated on wrong attempts, and nothing raises that
count until the claim loop lands — so at the shipped defaults neither control
can appear on this page at all, and a checkpoint could not look at either. Zero
opens both from the first render. The `configs` prop goes when the injection
does.

Expected — the SWAP model, EDITOR-FIRST: the editor mounts at load holding the
seed program (no lens is named in the props, so the home base is the default);
opening any lens from the Source select REPLACES the editor; closing — Edit
code, or the `—` none entry — brings the editor back with your edits intact; the
control row shows Generate code in editor mode and Edit code while an excursion
holds the pane, never both at once, because the editor is away exactly while an
excursion is open; Generate code opens the generator as the pane's third
occupant — seeded with the buffer exactly as typed, and left through Accept,
Discard or Edit code (Accept lands the candidate in the editor, everything else
leaves the buffer untouched); typing until the debounce settles re-renders the
phases; breaking the parse bars the phases downstream of the break, each naming
the parser's cause, and fixing it reopens them; the type toggle re-derives
immediately, closing an open lens OR an open generator first — as do level and
posture commits, so a derivation-context commit is the fourth way home from the
generator (opening a lens closes it too, but lands you in the lens); the level
selector lists both levels — the built-in JEJ and the injected scaffold — and
the closed face shows the selected level's live fit mark (each entry's own mark
rides the `data-level-mark` attribute, not visible text, so pick a level to see
one); pick a level, turn on strict, and type `debugger;` — the masked overlay
covers the content region, here the notes lens's recommendation, naming the
level and the violation; the strip goes inert and dim; and the Generate code
button, up in the live control row outside the overlay, dims and goes inert with
them — the editor, the level selector with its strict toggle, the type toggle
and the guide all stay alive; clicking the guide's reveal lists its four topics
at the bottom of the instrument.

The generator answers from the placeholder socket, so no model runs here and
every stage is scripted: every candidate carries a marker comment saying no
model ran — below your code, whatever the prompt asked for — and the line beside
it reads `Produced by placeholder in 1 attempt.` A prompt beginning `refuse:`
(lower-case, at the very start) answers with a refusal instead, which is how the
refusal path is reachable with no model behind it. The socket's own stages and
controls are exercised in isolation on the Generator — checkpoint page; here it
matters only as what the generator answers with.

The honored-focus variant (a lens open AT load) is prop-driven — add
`lens="notes"` to the harness to see it; it is jsdom-pinned and was
machine-replayed before this page flipped to the editor-first default.

export function InstrumentHarness() {
	const React = require('react');
	const StudyLenses =
		require('@site/src/lib/study-lenses/orchestrate/index.tsx').default;
	const scaffoldLevel =
		require('@site/src/lib/study-lenses/language-levels/scaffold/index.ts').default;
	const spellmeLens =
		require('@site/src/lib/study-lenses/lenses/spellme/index.tsx').default;
	const notesLens = {
		name: 'notes',
		applicability: () => true,
		phase: 'source',
		main: ({ embodiment, config }) => (
			<p data-notes-lens>
				notes (opened via {String(config.origin ?? 'the panel')}) — this program
				is {embodiment.facts.source.value.length} characters of source
			</p>
		),
	};
	notesLens.recommend = () => [
		{
			lens: notesLens,
			config: { origin: 'a recommendation' },
			relevance: 0.8,
			label: 'study the source',
		},
	];
	return (
		<StudyLenses
			configs={{ spellme: { oneMoreAfter: 0, skipAfter: 0 } }}
			languageLevels={[scaffoldLevel]}
			lenses={[notesLens, spellmeLens]}
			snippet={'const greeting = "hello";\nconsole.log(greeting);\n'}
		/>
	);
}

<BrowserOnly fallback={<p>loading the instrument…</p>}>
	{() => <InstrumentHarness />}
</BrowserOnly>
